# 真实工具调用 — 阶段 A

状态：PARTIAL。真实协议链路、校验和审计已运行，模型自主路由与回答质量尚不足以声称稳定。

AI Services 执行四个工具：searchCharacterKnowledge、searchGameMechanics、getGameEventInfo、queryGameMetrics。没有关键词路由器；工具由模型选择并生成参数。数据库工具在 SQL 模块配置前返回 BLOCKED，不用固定指标冒充真实查询。

每次执行包含 requestId、callId、工具名、实际参数、状态、耗时和原始结果。最多6个实际工具执行、最多6轮AI Services调用；单次模型调用60秒、最多1次重试；接口总期限240秒。取消接口任务不保证已发送的Ollama请求立即停止，底层仍受单次超时约束。错误回传使用安全摘要，不传数据库连接细节。输出必须符合 answer/citations/abstained/clarification 格式，引用必须来自本次实际检索。

20题在运行前固定于 evaluation/tool_tasks.json，包含自然语言单工具、多角色、多工具、无答案和注入任务。相同温度0、seed42、8192上下文、768输出token；预热不计入延迟。保留逐题原始结果及任务集SHA256。

选择准确定义为工具集合完全匹配，且满足标注的最少调用次数。参数schema指标按需要工具的任务统计，未调用也计失败；另报有具体字段标注的参数准确率。任务样本小、单次运行，不是总体可靠性估计。内存取Ollama /api/ps的size/size_vram，不等于Windows进程峰值RSS。模型升级和同模型提示对照分别保存，不能混淆贡献。

原版工具/API和测试保留，V2接口为/api/v2/agent。数据库、完整RAG和多轮模块的验收各有独立证据，不能用这20题的选择结果替代端到端任务完成率。

## 同模型工作流对照

随后固定1.7B、42条知识和真实SQL，重跑相同20题。两组具有相同游戏域名称和目录元数据，避免把模型升级或新增知识的差异算成工作流提升。单阶段guided vs 两阶段structured：

| 指标 | guided | structured |
|---|---:|---:|
| 工具集合/次数选择正确 | 5/20 | 12/20 |
| 任务级参数Schema | 6/19 | 14/19 |
| 有明确字段标注的参数 | 3/9 | 6/9 |
| 多工具选择集合/次数 | 1/2 | 1/2 |
| 无答案处理 | 0/2 | 2/2 |
| 最终格式/引用/证据门禁通过 | 1/20 | 17/20 |
| P95毫秒 | 16494.1 | 14894.2 |

原始summary字段output_schema_pass统计的是status=OK，含来源与证据门禁，不应称为纯JSON格式准确率。multi_tool_success只统计工具选择覆盖和最低次数，不是全部工具执行/答案成功。20题一次运行、小样本无显著性检验；不能写成生产准确率或稳定Agent。

两阶段让AI Services先以普通文本协议自主选择/执行工具，再由同一模型依据实际证据生成结构化Reply。应用不替模型选择工具，不从题库读取答案。未知角色事实/技能应拒答；模糊比较应追问。解析、引用、证据门禁不通过时reply=null，原始输出单独保留，不作为会话事实记忆。

证据：stage-a/final-guided-control、stage-a/final-two-stage。正式80题是另外的广覆盖评测，不能把这个开发集的60%当成80题工具选择率。运行时公开/api/agent也委托V2，不再用旧固定Synthetic样例当SQL结果；旧代码和原测试只作兼容保留。
